# Workers VPC and Gateway feasibility

## Findings on 2026-11-19

Wrangler 4.165.0 accepts `vpc_networks: [{ binding: "EGRESS", network_id: "cf1:network", remote: true }]` and its dry-run build identifies the binding as a VPC Network. The docs show the same syntax and outbound `EGRESS.fetch()`. The remote flag enables remote binding use in development and is explicitly disabled in the test harness. [Cloudflare VPC Networks](https://developers.cloudflare.com/workers-vpc/configuration/vpc-networks/)

Cloudflare lists Workers VPC as beta and available on Free and Paid Workers plans with no separate charge during beta. The public egress announcement describes Gateway routing for public hosts through the default virtual network. The VPC Network configuration page also notes an active Tunnel, Mesh node, or WAN on-ramp for reaching target services in the private-network setup. The public egress example does not require referencing or provisioning a connector. Our interpretation is to try the existing default network first. This account accepted the binding and reached a public origin through Gateway without provisioning a connector. The test used the existing account configuration and did not isolate any preexisting account dependencies. [Workers VPC overview](https://developers.cloudflare.com/workers-vpc/) · [Public Gateway egress announcement](https://developers.cloudflare.com/changelog/post/2026-06-05-gateway-egress/) · [VPC Networks](https://developers.cloudflare.com/workers-vpc/configuration/vpc-networks/)

Gateway applies matching DNS, network, HTTP and egress policies to Worker requests. A matching Gateway Forward rule drops Worker VPC HTTP traffic. Gateway Network logs identify the traffic source as Workers VPC. Network Session Logs can attribute traffic to the Worker by name and stable ID for recently deployed Workers. Public IPs may vary by request and do not establish whether Gateway was used. The Mac WARP result establishes only that client's earlier path. [VPC networks and logging](https://developers.cloudflare.com/workers-vpc/configuration/vpc-networks/) · [VPC troubleshooting](https://developers.cloudflare.com/workers-vpc/reference/troubleshooting/)

Fetch uses the Workers Request/Response interface. The feasibility Worker makes GET and POST requests, constructs headers explicitly, reads bounded response streams, sets manual redirect behavior, and passes an abort signal. Cloudflare's Fetch API supports `cache: "no-store"` for ordinary requests to non-Cloudflare origins. Its exact behavior through the VPC binding and on Cloudflare-hosted X assets needs live verification before relaying authenticated data. No application transcript cache is used. Streaming uploads, runtime header behavior, and the exact error shape of Gateway-denied payloads remain live integration checks. Ordinary fetch is used only by its explicit diagnostic endpoints. [Workers Fetch](https://developers.cloudflare.com/workers/runtime-apis/fetch/) · [Workers Request](https://developers.cloudflare.com/workers/runtime-apis/request/) · [Workers limits](https://developers.cloudflare.com/workers/platform/limits/)

The code uses HTTPS and standard certificate validation. Gateway may terminate and re-establish HTTPS when TLS decryption applies. Read-only API review showed TLS decryption and HTTP logging enabled. The IP probe appeared in Gateway HTTP logs. Cloudflare documents that the HTTP URL field stores the full request URL. Preserve verification and treat a certificate error as failure. If evidence warrants a policy exception, identify the exact host, traffic source, and required scope and request approval. Gateway's default PII redaction can hide a URL in a view while retaining its underlying value. [Gateway TLS decryption](https://developers.cloudflare.com/cloudflare-one/traffic-controls/http-policies/tls-decryption/) · [Gateway PII handling](https://developers.cloudflare.com/cloudflare-one/insights/logs/dashboard-logs/gateway-logs/manage-pii/)

## Cost and operational limits

Cloudflare lists 100,000 daily requests and 10 ms CPU per invocation on Workers Free. Paid starts at $5 USD/month per account, includes 10 million requests and 30 million CPU milliseconds per month, and charges $0.30 and $0.02 per additional million respectively. Cloudflare lists no separate Workers transfer charge. Workers have 128 MB memory, six simultaneous outbound connections per invocation, and 50 Free or 10,000 default Paid external subrequests. Our probes use at most three sequential subrequests. Caption parsing or a large HTML response can exceed Free CPU and must be measured in acceptance. A representative scan of 100 candidate videos with successful signed-out caption requests would be 100 Worker diagnostic runs and up to 300 outbound requests when run one route per video, assuming the same request sequence. The current diagnostic is fixed to one video. [Workers pricing](https://developers.cloudflare.com/workers/platform/pricing/) · [Workers limits](https://developers.cloudflare.com/workers/platform/limits/)

Zero Trust has separate entitlements. Cloudflare advertises Free for up to 50 users and pay-as-you-go pricing from $7 per user per month. Free Gateway HTTP logs are listed with 24-hour retention. Review actual log entitlements, account plan, any dedicated egress pricing or add-ons, and beta terms before production. No dedicated egress IP, log export or plan upgrade is in the proposed changes. [Cloudflare plans](https://www.cloudflare.com/plans/) · [Zero Trust logs](https://developers.cloudflare.com/cloudflare-one/insights/logs/)
